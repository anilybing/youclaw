# 工单分类与处理建议（support-ticket）

把客户粘过来的一堆反馈/工单/留言，快速**分好类、定好优先级、给出处理建议和转派对象**，并提炼共性问题，让不懂运营的团队一眼知道先处理什么、派给谁。

## 分类维度

| 类别 | 含义 | 典型信号 |
| --- | --- | --- |
| 售前咨询 | 下单前的问询 | 问价、规格、库存、能否发货 |
| 售后投诉 | 对已购的不满 | 差评、态度、体验差、要说法 |
| 退款退货 | 退货/退款/换货诉求 | 退款、退货、换货、不想要了 |
| 功能建议 | 期望改进/新增 | 希望能、建议加、要是有…就好 |
| Bug 报障 | 产品缺陷/故障 | 报错、闪退、打不开、不能用 |

## 优先级判定

| 优先级 | 判定标准 |
| --- | --- |
| 紧急 | 影响大面积用户/涉资金安全/舆情曝光/监管投诉/人身安全 |
| 高 | 已付费用户被阻断、明确投诉升级、临近时效的退款 |
| 中 | 单个用户功能异常、普通退换、需跟进但不阻断 |
| 低 | 一般咨询、功能建议、可批量统一答复 |

## 转派对象（按团队裁剪，缺则给通用角色）

- 售前咨询 → 销售/在线客服
- 售后投诉 / 退款退货 → 客服主管 / 售后专员
- 功能建议 → 产品经理
- Bug 报障 → 技术支持 / 研发
- 紧急/舆情 → 主管 + 相关负责人（并提示同步升级）

## 工作流

1. 逐条读取工单，**逐条**打上：类别 + 优先级 + 一句话处理建议 + 转派对象。
2. 建议要具体可执行（如"核实订单号后按七天无理由退款，运费按活动页"），而非空话。
3. 输出**结构化表格**（默认 Markdown）：

```text
| # | 工单摘要 | 类别 | 优先级 | 处理建议 | 转派对象 |
| 1 | 下单三天未发货，要催 | 售后投诉 | 高 | 查物流+主动致歉给确定发货时间 | 客服主管 |
| 2 | 希望支持货到付款 | 功能建议 | 低 | 记录需求，纳入排期评估 | 产品经理 |
| 3 | App 打开就闪退 | Bug 报障 | 紧急 | 收集机型/版本/录屏，立即上报 | 技术支持 |
```

4. 表格下方给**共性问题提炼**：哪些问题反复出现（如"发货慢"占比高）、可能的根因、批量改进建议（如更新 FAQ、优化发货流程）。
5. 给**处理顺序清单**：按优先级排出"先处理这些"的 Top 列表。
6. 需要落盘台账/派单表时调用 `office-excel`；共性问题若要沉淀成 FAQ，提示可用 `support-faq`；单条工单要写回复话术，提示可用 `support-reply`。落盘到「客服产出」目录。

## 红线（必须遵守）

- **拿不准就标"待人工确认"**：分类/优先级模糊时给出倾向 + 标注不确定，不硬判。
- **紧急项不得压低**：涉资金、安全、舆情、监管的一律按紧急上报并提示升级，宁可高报不可漏报。
- **只做分诊与建议，不代替决策与承诺**：处理建议里不擅自承诺赔付金额/时效，涉及让步注明"需授权"。
- 不臆造工单里没有的信息（订单号、金额、原因）；信息不足时在建议里列出"需补充的信息"。
- 保护隐私：整理时不外泄客户手机号/地址等敏感信息到无关产出。
