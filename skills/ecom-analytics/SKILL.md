# 电商销售报表分析（ecom-analytics）

把小白卖家从各平台后台导出的销售/流量表，变成一句话看得懂的**经营诊断报告 + 下一步该做什么**。计算在本地完成（复用 office-excel 技能），数据不出本机。

## 能回答的问题

- 哪些是爆款、哪些是滞销款（销量/销售额/毛利排行）
- 转化率、客单价、退款率异常在哪个商品/时段
- 环比/同比趋势（本周 vs 上周、本月 vs 上月）
- 流量来源效率（哪个渠道 ROI 高）
- 库存与动销预警（卖得快但库存低 / 压货）

## 工作流

1. **读表头**：用内置文档解析能力读取用户的 `.xlsx`/`.csv`，确认工作表与列名（列名大小写敏感），跟用户核对关键列的含义（如"实付金额""支付件数""访客数"）。缺列则说明哪些分析做不了。
2. **本地计算**：调用 `office-excel` 技能做确定性统计，避免把上千行原始数据塞进对话：
   - `summarize`：各列非空数/唯一值/数值列 sum·avg·min·max，先摸清数据规模与质量
   - `pivot`：按商品/类目/渠道/日期分组聚合（sum/count/avg），得出排行与结构
   - `filter`：筛出异常行（如退款率>阈值、转化<阈值）
   把中间结果表输出到「电商产出」目录。
3. **诊断解读**：基于计算结果（不是原始大表）做经营分析：
   - 用"二八法则"点出 TOP/尾部商品，给出**具体动作**（加推/改价/清仓/优化主图详情）
   - 指出异常并给可能原因与验证方法
   - 趋势用简单结论表达（"客单价连续两周下滑，主因 A 商品占比上升"）
4. **产出报告**：默认 Markdown「销售诊断报告」（现状概览 → 关键发现 → 问题 → 行动建议 优先级排序）。用户要 Word/正式报表时调 `office-doc`；要回填分析表时用 `office-excel` 产出的文件。
5. 含报表上传的分析不走工作台定时（附件是一次性的）；要周期性数据周报，可把固定分析口径写进提示词，借助数字员工记忆按需复跑。

## 红线（必须遵守）

- **数据不出本机**：全程零网络上传，计算走本地 office-excel 脚本。
- **不改原始文件**：所有产出写到「电商产出」目录的新文件。
- **结论有据**：每个判断都能对应到计算出的数字，不凭空下结论；数据不足以支撑时明说"当前数据无法判断，需要 X 列/更长时间窗"。
- 不虚构行业基准；给对比阈值时说明是经验参考值，建议用户以自己历史数据为基线。
