# 数据报告（data-report）

把一份表格数据变成「双击就能看」的可视化分析报告：单个 HTML 文件内嵌数据与图表，不依赖任何本地环境，浏览器打开即用。

## 工作流

### 1. 拿到数据

- **用户上传 `.xlsx`/`.csv`**：先用 office-excel 技能把文件转成可读数据——小表直接读取全部内容；数据量大（约 200 行以上）或需先加工时，用它的 summarize/pivot/filter 产出可嵌入报告的小结果表（原始明细不必全部塞进报告）。
- **用户直接粘贴表格文本**（Markdown 表格 / 制表符分隔 / CSV 片段）：直接解析使用。
- 没有数据时先向用户要数据，不要凭空开写。

### 2. 数据画像与目标确认

动笔前先输出数据画像，并与用户确认分析目标：

- 规模：行数、字段数
- 字段：每列名称、类型（数值/文本/日期）、缺失比例
- 疑点：明显异常值、重复行、格式不一致
- 基于画像提议 2~4 个分析角度（如「按月看趋势」「按渠道看构成」），等用户确认或调整后再产出；用户已经把需求说得很明确时可直接进入下一步。

### 3. 生成单文件自包含 HTML 报告

一个 `.html` 文件装下全部内容，页面结构从上到下：

1. **报告标题** + 生成日期 + 数据范围说明（数据来源、行数、时间窗）
2. **结论摘要**：3~5 条可执行洞察，每条 = 发现 + 数字依据 + 建议动作
3. **图表区**：2~4 张 ECharts 图，每张图上方配一句话解读
4. **数据明细表**：静态 `<table>`（数据量大时放聚合结果表并注明口径）

图表选型规则（按分析意图选，不堆图）：

| 分析意图 | 图表类型 |
| --- | --- |
| 趋势（随时间变化） | 折线图 |
| 构成（占比结构） | 饼图 / 环形图 |
| 对比（类别间大小） | 柱状图 |
| 相关（两个数值字段的关系） | 散点图 |

技术要求：

- 数据以 `const rawData = [...]` 形式内嵌在 `<script>` 里，不引用任何外部数据文件
- ECharts 通过 CDN `<script src>` 引入（如 `https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js`），并用 `onerror` 追加一个备用 CDN（如 `https://cdn.bootcdn.net/ajax/libs/echarts/5.5.1/echarts.min.js`）
- 页面简洁美观：统一配色、适当留白、图表容器固定高度，窄屏也可读

### 4. 写入「数据报告」目录

- 产物写到工作区「数据报告」目录，目录不存在先创建
- 文件名 = 中文主题 + 日期，例如 `数据报告/渠道销量分析报告_2026-07-08.html`

### 5. 回复用户

- 给出产物**绝对路径**，提醒用户双击文件即可用浏览器打开
- 附上与报告一致的 3~5 条结论摘要
- 说明：图表需联网加载图表库；离线打开时结论与明细表仍可正常查看

## 红线（必须遵守）

- **不编造数据**：报告里每个数字都必须来自用户数据或对其的真实计算；缺数据支撑的分析角度明说做不了，不用假数据凑图。
- **小样本注明局限**：样本少（约 30 行以内）或时间跨度过短时，在结论摘要显著位置注明「样本量有限，结论仅供参考」。
- **必须可降级**：结论摘要与数据明细表写成**静态 HTML**，不依赖 JS 渲染；CDN 加载失败时报告仍能看到全部结论和数据，只是没有交互图表（在图表容器里给「图表加载失败，请联网后刷新」的占位提示）。
- 不改用户原始文件；产出只写「数据报告」目录的新文件。
