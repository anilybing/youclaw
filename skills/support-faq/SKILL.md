# FAQ 知识库生成（support-faq）

把零散的产品说明、客户常问、历史工单聊天记录，整理成一套**能直接导入帮助中心/客服机器人**的结构化 FAQ。目标是标准答案统一、近义问题不重复、按主题好检索。

## 每条 FAQ 的标准结构

| 字段 | 说明 |
| --- | --- |
| 问题 | 用客户真实说法，简洁到一句 |
| 标准答案 | 口径统一、可直接发送，步骤类用编号 |
| 分类 | 所属主题分组（见下） |
| 关键词 | 3~6 个检索词/近义词，供搜索与机器人命中 |

## 常用主题分组（按业务裁剪）

- 售前咨询（价格、规格、库存、发货时效）
- 订单与支付（下单、改单、发票、付款问题）
- 物流配送（发货、查件、签收、丢件）
- 退换与售后（退货政策、退款进度、保修）
- 使用与故障（安装、使用方法、常见故障排查）
- 账户与活动（注册、会员、优惠券、活动规则）

## 需要的输入（缺什么一次性问全）

- **原始素材**：产品说明书/详情页、常见问题清单、历史工单或客服聊天记录（越全越准）。
- **业务口径**：政策类答案的标准口径（退换时效、保修范围、发货时间），缺的标【待确认口径】而非编造。
- **用途**：导入哪种载体（帮助中心网页 / 客服机器人 / 内部话术库），影响答案长度与格式。

## 工作流

1. 收集并通读素材，抽取所有真实问题与答案要点。
2. **去重合并近义问题**：把「怎么退货 / 退货流程 / 如何申请退款」等归并为一条，答案取并集、口径统一；合并时保留最口语的一种作为主问题，其余转为关键词。
3. **按主题分组**并排序（高频问题靠前）。
4. 为每条补齐标准答案与关键词；答案做到**不需上下文即可独立看懂**，步骤类用编号列表。
5. 输出结构化结果，默认 **Markdown**，便于直接导入帮助中心：

```text
## 退换与售后

### 支持七天无理由退货吗？
支持。符合完好标准的商品，签收后 7 天内可申请无理由退货，运费规则以活动页为准。
- 分类：退换与售后
- 关键词：七天无理由、退货、退款、无理由

### 退款一般多久到账？
审核通过后 1~3 个工作日原路退回，具体到账时间以支付渠道为准。
- 分类：退换与售后
- 关键词：退款、到账、多久、进度
```

6. 需要表格台账（问题/答案/分类/关键词四列）时，调用 `office-excel` 导出；需要成文帮助手册时调用 `office-doc`。落盘到「客服产出」目录。
7. 交付时附**覆盖度小结**：共整理多少条、合并了多少近义项、还有哪些【待确认口径】需用户补。

## 红线（必须遵守）

- **答案口径以用户提供为准，不编造政策**：时效、保修、赔付等硬政策缺失时标【待确认口径】，绝不臆造具体数字。
- 合并近义问题时**不得丢失差异化信息**（如"运费谁承担"的不同情形要分条或在答案中说明）。
- 标准答案**中立、可直接发送**，不含内部备注、不含未确认承诺。
- 涉及价格、活动规则等易变内容，在答案中提示"以商品页/活动页实际为准"，避免过期误导。
